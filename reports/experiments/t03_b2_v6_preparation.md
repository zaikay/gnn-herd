# B2 learned/identity screen and campaign preparation

2 November 2026. Implementation follows the researcher's supplied architecture and final selection rules in [protocol v6](../protocol/protocol_v6_b2_graph_and_campaign.md). Preparation only: no new study fits, GPU operations or test forecasts/losses.

Learned uses a dense, time-invariant row-softmax adjacency, computed once per forward pass. Self and unknown-area source columns are masked before softmax. Geographic isolates receive learned neighbours. Identity concatenates the same two embeddings into twenty local GRU input channels, with no neighbour correction. Original B2 scaling and raw-count Poisson objective remain unchanged.

Parameter counts, generated by `models.b2_adaptive.parameter_counts`:

| Model | Embedding parameters | Total parameters |
| --- | ---: | ---: |
| B2 learned | 52,820 | 68,000 |
| B2 identity | 52,820 | 71,072 |

Total counts are deliberately not matched: identity widens the GRU and removes the neighbour head. Embedding counts match exactly. Initialisation is independent normal with standard deviation 0.01, fixed in the note before any fit.

The identity safety stop precedes campaign fitting: at least 2% lower MAE than real requires researcher review. Otherwise learned is main and both new conditions join only if learned beats both real and identity. Learned beating real but failing identity retains real and excludes both new conditions. No graph remains a control. All scores use both anchors and all twelve monthly horizons.

One original laptop, all seeds 11/29/47. Four-condition campaign: 144 fit identities, four eligible anchor reuses, 140 new fits. Six-condition campaign if learned qualifies: 216 identities, eight reused, 208 new. Each condition uses 36 quarterly/seed fits at configuration 3 and 100 epochs. Saved scales remain fixed per refit. Immutable checkpoint pointers reuse exact eligible seed-11 anchor fits. Source/data/protocol/hardware and reuse hashes guard resumptions. The screen and campaign use separate artifact roots and the existing shared GPU lock. Five-epoch checkpoints use the existing tested RNG/Adam restoration mechanism.

Prepared reports: `evaluation.b2_graph_screen_report` compares four conditions at each anchor, all horizons/total and maturity groups, signed error, training curves, measured cost and peak GPU memory. It writes the fixed decision and an anchor-based campaign time projection. `evaluation.b2_gate_c` refuses combined results until every retained condition is complete. It reports all baselines/conditions with MAE, MASE, pooled RMSE and seed spread, spatial diagnostics/maps, paper candidates and the single declared 20- or 28-test DM/Holm family. Screen and campaign commands never access final-test origins.
